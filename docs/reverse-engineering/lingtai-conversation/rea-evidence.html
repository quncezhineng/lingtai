方法与工具状态

该 Codex 运行时没有注册可调用的 mcp__rea__* 工具；直接调用会返回 unsupported call。因此使用 REA 6.3.0 的独立 stdio MCP 服务进行静态分析。服务暴露了 139 个工具，其中本次用到：

  • analyze_javascript_application：分析文件集合并构建应用图。
  • inspect_analysis_view：在完整响应超过 stdio 预算时投影摘要证据。
  • trace_application_feature：从入口种子追踪调用路径与终端路径。
  • export_evidence_bundle：导出可复核的证据包。

整个项目与 web/src 的全量分析都超过 300 秒期限；因此创建只读的五文件夹具，聚焦对话链路。这不是对全仓库的完整覆盖，但对前端对话核心路径具有直接证据价值。

工程推断

  • 时间线是服务端的事实源，前端 store 是可重建的投影；这从 hello.state、历史分页和重连重载三条路径可以相互印证。
  • 流式临时文本只存在于广播层，因为持久化事件只在 on_assistant_message() 中写入；因此崩溃恢复不包含半截 delta。
  • onopen 重置 attempt 会产生 open-then-close 高频重连风险；这是代码路径推断，不是实际网络观测。
  • 单进程 EventBus 不支持跨实例顺序与共享游标；多实例部署需要额外 pub/sub 和序列分配层。
  • HTML artifact 的 sandbox 设计把“渲染”与“同源权限”分离，属于明确的安全边界，不是仅靠 CSP 的装饰性配置。

未知项与未覆盖范围

语义未知：语义图保留 2,946 个未知节点，说明部分动态分派、跨文件别名或运行时构造无法静态解析。不能把未知节点当作“不存在”。
运行时未验证：没有在真实浏览器中测量首帧延迟、断线恢复时间、代理缓冲、弱网重连或高并发内存曲线。
部署未验证：没有验证反向代理、TLS 终止、HTTP/2、跨区域网络和多实例一致性。
全仓库未覆盖：只对五文件夹具做了 REA 图分析；服务端结论来自直接源码阅读与行号定位，不是 REA 对 Python 文件的 AST 分析。
行为未触发：没有向目标项目发送消息、上传附件、执行工具或写入数据；所有结论均为只读静态分析。

复现与复核建议

  1. 在允许启动 stdio MCP 的环境中运行 REA 6.3.0，并确认工具清单包含 139 个工具。
  2. 重新分析五文件夹具，核对 parent evidence 的 AST 节点数、发现数与完整性计数。
  3. 用 inspect_analysis_view 读取摘要证据，再用 export_evidence_bundle 导出完整 bundle。
  4. 从 api.ts 重新执行 feature trace，核对 183 节点、338 边、89 终端路径与 139/471 事实计数。
  5. 运行时验证应另建测试环境，覆盖 WebSocket 首帧认证、4401/4404、断线重载、慢消费者与 HTML artifact 隔离。

静态证据只能证明“代码中存在这些路径”。任何“稳定运行”“高并发可用”“弱网可恢复”的结论都必须由独立运行测试支撑。
