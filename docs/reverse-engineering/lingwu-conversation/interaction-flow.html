Artifact 03 · Interaction flow

端到端交互与流式协议

一条消息经过 REST 写入、线程队列、模型运行、WebSocket 增量推送、最终事件替换与历史分页恢复。下面把每个网络边界和前端决策点拆开。

总览 架构依赖 业务逻辑 服务端运行时 前端渲染 REA 证据 分析数据

前端不做模型调度，也不缓存完整对话事实；它维护连接状态、临时流、当前线程事件与 UI 偏好。服务端负责持久化、线程串行、状态收敛与实时扇出。

发送接口只等待“入队完成”，不等待模型结束。因此即使模型运行数分钟，HTTP 请求仍能快速返回；真正的增量内容通过 WebSocket 独立到达。

WebSocket 握手与认证

1 · 建立连接

客户端连接同源 /ws，令牌不放在 URL 查询参数中，避免被反向代理访问日志记录。

2 · 首帧认证

客户端发送 {"kind":"auth","token":"..."}。服务端最多等待 10 秒；失败以 4401 关闭。

3 · 订阅与快照

服务端订阅 EventBus，先发送 {"kind":"hello","state":...}。快照包含线程、待审批、目标、设置、设备、hub 等全局状态。

4 · 双工收发

独立 pump 任务持续把队列消息写入 socket；主循环读取客户端命令，并通过同一把锁串行化发送，避免并发写帧。

5 · 清理

finally 中取消 pump、取消订阅、分离设备连接。认证失败、网络断开和异常关闭都不会遗留订阅者。

前端接收、归并与渲染

接收

connectWs() 对每条消息做 JSON 解析，格式异常则忽略；StoreProvider 把同一事件循环内到达的消息放入队列，用 0ms 定时器批量 dispatch。

流开始

stream_start 创建 {id, text:"", ended:false}；delta 只在 id 匹配时追加，若 id 变化则新建流，避免旧流污染新回复。

流结束

stream_end 标记 ended:true；discard 或空文本立即删除。非空流保留到头像正式消息到达，以减少闪烁。

正式替换

event/update 到达 assistant 事件时，如果其 id 等于当前流 id，reducer 在同一个新状态里清除流并 upsert 事件。

滚动跟随

用户距离底部小于 120px 时自动跟随；超过 400px 才显示 “Latest” 按钮；ResizeObserver 在内容尺寸变化后重新贴底。

无障碍

LiveReply 使用 role=status、aria-live=polite、aria-atomic=true，开始时报“正在写回复”，结束后一次播报完整文本，不逐 token 打断。

断线、重连与历史补偿

上游的重连策略是“恢复连接 + 重载当前线程时间线”，不是按增量序号补洞。这个差异决定了它的恢复语义。

历史分页与“加载更早的消息”

GET /api/threads/{id}/events 的 limit 被限制在 1 到 1000，默认 200；before 是事件 id 游标，服务端在该 id 之前截断后取尾部。返回的 has_more 仅根据当前时间线长度与本次返回数量比较。

前端首次打开线程加载 150 条；点击“加载更早的消息”时把当前最旧事件 id 作为 before 继续请求。新的加载会生成 generation，防止旧请求晚到后覆盖新结果。

边界

如果 before 不在当前 2000 条保留窗口内，服务端找不到索引，会退化为返回当前尾部的 limit 条；客户端因此可能收到重复页，需要按事件 id 去重。
