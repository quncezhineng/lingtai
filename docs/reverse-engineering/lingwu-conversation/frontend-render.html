前端渲染与交互状态深潜

上游前端不是“收到整条回复再渲染”，而是把持久化时间线、临时 delta、工具卡片、审批状态、文件查看器和滚动位置组合成一个可恢复的 UI 状态机。

总览 架构依赖 业务逻辑 交互流程 服务端运行时 REA 证据 分析数据

状态分层

AUTHBearer token、首帧认证、401 重新登录
TRANSPORTWebSocket 生命周期、重连退避、REST 回退
TIMELINE按线程缓存事件、分页、按 id upsert
LIVE临时流、状态、审批队列、holds、working presence

UI 事件列表是服务端时间线的投影；临时流是“进行中的回复”；审批队列和 holds 是跨线程的派生视图。三者分开存放，避免把临时状态误认为持久事实。

认证、令牌与文件地址

令牌获取：getToken() 先从 URL fragment 的 #token= 读取，写入 localStorage 后用 history.replaceState 从地址栏移除；fragment 不会发往服务器，比查询参数更安全。
请求封装：request() 自动添加 Bearer 头；401 抛 AuthError；网络失败统一显示 “Cannot reach your LingWu right now.”；服务端 detail 只展示可读句子，验证错误数组不会原样泄漏。
内联资源：fileUrl() 不把令牌放进 URL，而是调用 signedParams() 生成带路径绑定的 exp/sig。图片、PDF、iframe 和下载都通过这条签名链路。
文本读取：api.fileText() 反过来使用 Authorization 头读取原始文本，供 Markdown、代码和 HTML 预览使用，避免把带签名的 URL 暴露给应用逻辑。

传输选择与重连

SEND

发送路径

无附件且 WebSocket 可写时走 {"kind":"send"}；有附件或 socket 不可用时回退到 REST。sendViaCloud 始终走 REST，以便同步返回云端拒绝原因。

APPROVAL

审批路径

优先通过 WebSocket 发送 approval；socket 不可用时回退到 POST /api/approvals/{id}。

RECONNECT

重连

普通关闭使用 500ms 起的指数退避，15s 封顶；4401 进入认证错误；4404 标记运行时结束并停止重试。

SYNC

重连补历史

重连成功后如果当前线程已加载，重新请求 150 条历史，补齐断线期间已持久化的审批、产物和最终回复。

attempt 0 → 500ms
attempt 1 → 1000ms
attempt 2 → 2000ms
attempt 3 → 4000ms
attempt 4 → 8000ms
attempt 5+ → 15000ms

onopen:
  send first-frame auth
  attempt = 0
  onOpen
已识别缺陷：onopen 立即把 attempt 重置为 0。如果代理接受连接后马上关闭，客户端每次都只等 500ms，形成高频重连。健康实现应在收到首条有效数据后才清零，或使用独立稳定连接计时。

事件归并与顺序

upsertEvent() 先按事件 id 查找：存在则原位替换，不存在则追加。唯一例外是跨设备同步事件：如果它的时间早于当前列表末尾，就按 ISO 时间插入，避免“刚从云端拉到的旧消息”出现在最新位置。

idx = events.findIndex(e => e.id === incoming.id)
if idx >= 0:
    replace(events[idx], incoming)
else if incoming.synced and incoming.ts < events[-1].ts:
    insert at first position whose timestamp is later
else:
    append incoming

只有已经加载过该线程历史的页面才把实时事件合入 state.events；未打开线程仅更新线程列表、审批队列和 Feed 计数，等用户打开时再拉历史。这减少后台线程的内存占用。

hello 快照的语义

hello 会清空临时流，防止把断线前的半截气泡当成仍然有效；线程事件缓存不一定清空，重连后的主动 loadEvents 会用服务端历史替换。审批、holds、hands、hub 和 working 状态由快照重建。

流式回复 reducer

stream_start 创建 {id,text:"",ended:false}。即使同一线程以前有流，也直接覆盖，表示服务端开始了新的回复。
delta 仅在 id 匹配时追加；id 不匹配时用当前 delta 新建流，避免旧流被错误拼接。
stream_end 标记 ended。如果 discard 或文本为空，立即删除；否则保留到正式 assistant 事件到达，减少气泡闪烁。
assistant event 若事件 id 与流 id 相同，在应用事件的同时清空临时流，让正式消息接管。
status 当流已结束且线程不再是 working，顺手清理残留流；working → idle 触发完成动画和任务计数。

批量渲染

WebSocket 突发（例如一次历史 tail 带来 300 条 event）先进入本地队列，用 0ms 定时器合并到同一轮 dispatch。文本 delta 最多延迟几毫秒，但避免每帧触发一次 React 树更新。

距底 120px 内自动跟随；超过 400px 显示 Latest；ResizeObserver 在图片、字体或代码块改变高度后补一次贴底。

产物卡片、Markdown 与安全预览

  1. ChatScreen 从当前线程的 artifact 事件中汇总路径集合，传给所有 AssistantBubble。
  2. Markdown 识别回复中的相对链接和 inline code；若匹配线程已有文件，渲染为内部按钮，否则按普通外链新窗口打开。
  3. ArtifactCard 展示类型、标题、路径；HTML/图片显示缩略预览，其他类型显示文件图标。
  4. FileViewer 是全局 modal：图片按 URL 加载，PDF 用 iframe，文本/代码/数据用 fileText()，HTML 用 srcDoc。
  5. HTML sandbox 为 allow-scripts allow-popups allow-forms allow-modals，刻意不含 allow-same-origin；脚本运行在 opaque origin，不能读取应用令牌或同源 API。
  6. 查看器带焦点陷阱与 Escape 关闭；非 HTML 文件可“新标签打开”，所有文件可下载。
信任边界：产物 HTML 可以运行脚本和弹窗，但无法读取同源存储；如果未来加入 allow-same-origin、把 artifact 放到应用主域，或允许 iframe 继承权限，安全边界会被破坏。

前端一致性与异常处理

场景前端行为剩余风险
重复事件 id原位置替换若服务端 id 不稳定，会覆盖错误事件
流 id 变化新建流，不拼接旧文本旧流残留需 status 或 stream_end 清理
断线重连恢复 socket 后重载当前线程历史未持久化 delta 无法恢复

前端设计缺口与改造建议

  1. 为每个流事件增加单调序号与 run id，重连时只请求缺失后缀，而不是整段历史。
  2. 把重试计数清零移到“收到有效帧”之后，并加入抖动与最大重试上限。
  3. 为 send 增加客户端幂等键，避免 WebSocket 断线重发造成重复用户消息。
  4. 为历史事件和临时流增加字节预算，而不仅按线程/条数控制。
  5. 当流式文本与最终持久化消息不一致时，增加完整性校验和可见警告。
  6. 将审批与问题的等待超时在 UI 上显式倒计时，减少“卡片仍 pending 但服务端已过期”的认知差。
  7. 为弱网增加半开连接检测；仅依赖 TCP 关闭事件无法发现代理静默丢包。

这些建议是逆向后的工程判断，不代表上游当前缺陷清单或已排期事项。

前端深潜基于 React/TypeScript 源码静态阅读；未在真实浏览器或移动设备上执行运行时验证。
